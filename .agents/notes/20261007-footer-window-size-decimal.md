# Footer 窗口大小缩写：十进制阈值 + 四舍五入（163072 → 163K）

## 一句话结论

- `formatWindowSize` 由「按 1024 / 1048576 整除探测」改为「十进制阈值 + 四舍五入缩写」：`163072` 由原样吐出 `163072` 改为 `163K`，缩写统一大写 `K`、不带尾随 `.0`。

## 背景

- 旧实现只在「整除」时才缩写：`size % 1048576 === 0` → `M`，`% 1000000 === 0` → `M`，`% 1000 === 0` → `K`，`% 1024 === 0` → `K`，其余原样输出。
- 结果是常见的二进制窗口尺寸落不进任何整除分支，footer 直接吐出原始数字：`163072`（≈159K）显示为 `163072`，既长又难以人眼判读。用户明确要求 footer 的窗口大小一律按十进制缩写显示。

## 决策

- 行为规格（本次定稿）：

  | 入参区间 | 输出 | 例 |
  | --- | --- | --- |
  | 非 number / 非有限 / `<= 0` | `String(size)` 透传 | `0` → `0`，`-1000` → `-1000` |
  | `< 1000` | 原样数字串 | `999` → `999` |
  | `[1000, 1000000)` | 十进制 `K`，`Math.round(size / 1000)`；进位到 `1000` 时输出 `1M`（绝不输出 `1000K`） | `163072` → `163K`，`128000` → `128K`，`65536` → `66K`，`999999` → `1M` |
  | `>= 10000000` | 十进制 `M` 取整 | `10485760` → `10M`，`9999999` → `10M` |
  | `[1000000, 10000000)` | 十进制 `M`，按十分位四舍五入（`Math.round(size / 100000) / 10`），尾随 `.0` 自然消失 | `1048576` → `1M`，`1500000` → `1.5M`，`2097152` → `2.1M` |

- 动机：footer 的空间有限，窗口大小的作用是让人一眼读出量级；十进制阈值 + 四舍五入保证任意入参都有紧凑、单调可读的输出，不再出现「恰好整除才缩写」的空洞。
- 依据（用户明确要求的显示规则）：一律十进制缩写（1000 / 1000000 进制）、四舍五入、单位用**大写 `K`**、**不带尾随 `.0`**（`1048576` 显示 `1M` 而非 `1.0M`）。
- 十分位取整用 `Math.round(size / 100000) / 10` 而非 `Math.floor(m * 10) / 10`：二进制浮点漂移会让后者少掉十分之一（`1900000` → `1.8M`），前者稳定得 `1.9M`；`10 / 10` 字符串化为 `"1"`，因此 `1048576` 自然得到 `1M`，无需额外去尾。
- 涉及的文件与函数：
  - `extensions/cache-guardian.ts`：`formatWindowSize`（本次改动本体）；唯一调用点 `footer` 渲染中的 `` `${Math.round(cuPercent)}%/${formatWindowSize(cu.contextWindow)}` ``（约 L843）。
  - `test/hit-rate.mjs`：`7a. formatWindowSize tests` 断言块（二进制幂改为十进制缩写期望，新增 `163072`/`10485760`/`9999999` 等边界）。
  - `test/cache-guardian.mjs`：footer 渲染断言中窗口大小期望由 `128K` 改为 `131K`（`131072` 按十进制缩写为 `131K`）。

## 被放弃的方案（必填）

- 保留「整除探测」并追加小数分支：仍然存在整除优先导致的量级不一致（`1500000` 会走 `%1000` 分支得到 `1500K`，而不是 `1.5M`），与「一律十进制缩写」冲突，放弃。
- 复用 pi 官方 `formatTokens`：官方实现为小写 `k`，且整百万输出 `1.0M`，与用户明确要求（大写 `K`、无尾随 `.0`）冲突，放弃（登记为 O-3）。
- 把 `999999` 的进位口径改成严格 `>= 1000000` 才进 `M`：会产生 `1000K`，与规格冲突，放弃（登记为 O-1）。

## 遗留清单

1. **C-1**：`extensions/cache-guardian.ts` doc 注释里保留旧 1024/1048576 方案说明，维持现状。
2. **C-2**：部署需 `pnpm sync` + 重启 pi 才生效（本次已执行 sync，重启由用户择时）。
3. **O-1**：`999500` 因四舍五入提前显示 `1M`，维持现状（改成严格 ≥1000000 会产生 `1000K`，与规格冲突）。
4. **O-2**：非 number 运行时入参透传 `String(size)`，与旧实现一致、不在本次范围。
5. **O-3**：存在更小的替代路径（复用 pi 官方 `formatTokens`），**不采用**，因官方为小写 `k` 且整百万输出 `1.0M`，与用户要求冲突。
